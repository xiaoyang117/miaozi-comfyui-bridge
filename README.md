# 喵梓 · ComfyUI 创作工作台

用自然语言描述画面，让 LLM 写出绘图提示词，再交给 ComfyUI 生成图片。
喵梓把配置、会话历史、角色资料和工作流参数放在一个网页里，
方便在电脑上连续创作，也支持手机和平板通过局域网使用。

网站运行在你的电脑上。LLM 可以连接本地模型或远程的 OpenAI 兼容 API；
使用远程 LLM 或图片识别服务时，相应的文字或参考图会发送到你配置的服务。

## 主要功能

| 功能 | 可以做什么 |
| --- | --- |
| 自然语言生图 | 同时生成英文绘图提示词和中文画面说明 |
| 会话与上下文 | 保存创作历史、搜索和重命名会话，在同一会话里继续修改画面 |
| IP 创作空间 | 按访问 IP 分别保存会话、图片、NSFW 开关和工作流创作参数 |
| NSFW 模式 | 默认关闭；开启后允许按用户明确要求生成成年人题材提示词 |
| 角色资料 | 从本地角色库匹配特征，一次最多匹配四位角色 |
| 常驻正向内容 | 每次新创作加入质量词、风格词或其他固定内容 |
| 再次生成 | 复用已保存的提示词，跳过 LLM，随机化种子后重新出图 |
| 工作流控制 | 选择工作流，识别实际出图支路的尺寸节点并调整分辨率 |
| 多个 LoRA | 读取 ComfyUI 的 LoRA 列表、调整权重，或临时添加 LoRA 节点 |
| 二次采样 | 调整已有二采，或在支持的工作流中临时加入放大和二采 |
| 参考图 | 配置视觉模型后，把上传图片的识别文字用于提示词生成 |
| 本地插件 | 在网页管理启停和配置，扩展提示词、工作流、结果和网页面板 |
| 代理更新 | Windows 更新脚本支持 HTTP(S) 代理，并保留本地数据 |

## 快速开始

### 1. 准备环境

- **Python 3.10 或以上**：安装后应能在终端运行 `python --version`。
- **ComfyUI**：先确认自己的模型和工作流能在 ComfyUI 中正常出图。
- **LLM 服务**：支持 OpenAI 兼容的 `/chat/completions` 接口；
  可使用 llama.cpp、Ollama、LM Studio 提供的兼容接口，或远程 API。

喵梓不会替你启动 ComfyUI、下载绘图模型或启动 LLM。
只做文字生图时，不需要先安装 MCP、建立角色库或配置视觉模型。

### 2. 下载并启动网站

从 [GitHub 仓库](https://github.com/xiaoyang117/miaozi-comfyui-bridge)
选择 **Code → Download ZIP**，解压到一个固定目录。
也可以使用 Git：

```bash
git clone https://github.com/xiaoyang117/miaozi-comfyui-bridge.git
cd miaozi-comfyui-bridge
```

**Windows：**双击项目根目录的 [`start.bat`](start.bat)。
首次缺少网站依赖时，脚本会通过清华 PyPI 镜像安装；
启动后自动打开 <http://127.0.0.1:5000>。关闭启动窗口即可停止网站。

**手动启动：**在项目根目录运行，Windows、Linux 和 macOS 均可使用：

```bash
python -m pip install -r server/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python server/app.py
```

启动脚本对 `127.0.0.1:8188` 和 `127.0.0.1:8080` 的检查只是提示。
如果使用其他端口或远程模型，在网页填写实际地址即可。

### 3. 填写连接配置

打开网页的「配置」页：

| 配置 | 怎么填写 |
| --- | --- |
| LLM → API 地址 | 填接口基础地址，例如 `http://127.0.0.1:8080/v1` |
| LLM → API Key | 按服务要求填写；服务没有鉴权时可留空 |
| LLM → 模型名称 | 填模型服务接受的实际名称或已配置的模型别名 |
| ComfyUI 地址 | 同一台电脑常用 `http://127.0.0.1:8188` |
| 启用 MCP | 初次使用可关闭，先使用 HTTP 直连 |

API 地址应包含服务要求的前缀，例如 `/v1`；
程序会在后面追加 `/chat/completions`，不要填写完整的聊天请求地址。
本机和远程 LLM 都使用这三个字段，不需要切换连接模式。

点「保存配置」。如果改了 MCP 开关，保存后再点「重启引擎」。
然后分别测试 LLM 和 ComfyUI 连接；**ComfyUI 的测试使用已保存的地址**。

### 4. 选好工作流，生成第一张图

按下一节准备 API 格式工作流，在创作页选择它，再选择分辨率。
第一次可以先关闭「角色搜索」和「上下文」，输入一段描述，例如：

> 一只橘猫坐在洒满阳光的窗台上，温暖的绘本插画风格。

点击「生成图片」。结果会显示图片和画面说明；
英文提示词可以展开查看或复制。后续可在同一会话继续创作。

## 准备 ComfyUI 工作流

喵梓使用 **ComfyUI API 格式的 JSON 工作流**。

1. 在 ComfyUI 中确认工作流能正常出图。
2. 在需要填入正向提示词的文本节点里，写入 `114514.1919810`。
3. 用 **Save (API Format)** 或对应的 API 导出功能保存 JSON。
4. 把文件放到项目的 [`workflows/`](workflows/) 目录，或在配置页填写文件路径。
5. 在「工作流与占位符」中，确认提示词占位符一致，并填写输出图片的「保存节点 ID」。
6. 保存配置，刷新工作流列表，在创作页选中它。

普通画布导出的 `nodes` / `links` 格式不能直接用于出图。
API 格式按节点 ID 保存，节点中包含 `class_type` 和 `inputs`。
工作流里的模型文件和自定义节点也必须已经安装到 ComfyUI。

默认提示词占位符是 `114514.1919810`，可以在配置中更改。
程序替换这段文字，同一文本节点里的其他内容会保留；
例如 `masterpiece, best quality, 114514.1919810`。
只把占位符放在需要替换的地方，负向提示词可以在工作流中自行维护。

项目带有 [`MIAOMIAO.json`](workflows/MIAOMIAO.json) 作为示例，
默认保存节点 ID 是 `66`。示例依赖它所使用的模型和自定义节点，
包括 `DanbooruBrowser`，下载源码后不能保证直接出图；
也可以换成你自己已经能运行的工作流。

## 开始创作

基本流程：

```text
本轮描述 + 可选的参考图识别、角色资料和历史
  → LLM 生成英文提示词与中文说明
  → 加入常驻正向内容
  → 处理工作流尺寸、LoRA 和二采参数
  → ComfyUI 出图
  → 保存图片与会话历史
```

### 四个创作开关

| 开关 | 作用 |
| --- | --- |
| 角色搜索 | 使用已建立的角色库检索和注入角色特征；配置页也须启用角色库检索 |
| 上下文 | 带入同一会话最近几轮成功创作的描述和提示词，默认两轮；轮数设为 `0` 时不带历史 |
| 精细还原 | 让 LLM 更详细地保留角色外观特征；不会增加分辨率或采样步数 |
| NSFW | 默认关闭，按当前 IP 保存；开启后允许按明确要求表达成年人题材，不会自行加入成人内容 |

内置指令优先遵循本轮要求，历史和角色资料用于补充。
没有角色资料时，可用「自定义系统提示词」替代默认指令；
填写后也会替代这一分支的精细还原模板。
NSFW 模式规则对内置和自定义提示词均生效。
关闭 NSFW 后，上下文会跳过标记为 NSFW 的历史轮次；
旧图仍可在自己的历史里查看，标记为 NSFW 的图片须重新开启开关才能再次生成。
开关控制 LLM 的提示词模式，不检测输出图片，也不绕过模型服务的限制；
工作流已有的提示词、常驻正向内容和插件仍按原配置执行。

### 常驻正向内容

在「配置 → 提示词风格 → 常驻正向内容」填写：

```text
masterpiece, best quality, cinematic lighting
```

它会放在每次新生成的正向提示词前，留空则不添加。
这里可以放质量词、风格词或其他长期使用的内容；
若工作流里已经写了相同文字，删掉一处以免重复。

### 画面说明与再次生成

- **画面说明**由 LLM 在出图前撰写，表示预期画面，不是对实际成图的识别结果。
  模型只返回纯文本提示词时仍可出图，但没有画面说明。
- **再次生成**直接复用该结果保存的完整提示词和说明，
  跳过 LLM、角色检索及参考图识别，并随机化工作流中的数值型 `seed` / `noise_seed`。
- 再次生成复用记录中的工作流路径、尺寸、LoRA 和二采参数；
  旧记录缺少这些信息时使用当前配置补足。
- 修改常驻正向内容或提示词插件配置后，旧图的再次生成仍沿用旧提示词。
  想使用新内容，请发起新创作。

## 分辨率、LoRA 与二次采样

这些设置位于创作页。点击「保存此工作流参数」可按当前 IP 和工作流分别记住设置；
也可以不保存，直接用于本轮。程序修改提交给 ComfyUI 的工作流副本，
不会改写原始 JSON 文件。

### 分辨率

程序沿保存图片节点和采样器的连接，识别实际出图支路的尺寸输入，
支持常见的 `EmptyLatentImage`、`EmptySD3LatentImage`，
也会跟踪可识别的整数节点和 Reroute 连接。

展开「工作流尺寸与 LoRA」可查看识别结果并选择尺寸节点。
选择「保持工作流原尺寸」时不自动改宽高。
复杂尺寸计算或宽高共用同一个整数节点时，可能需要在 ComfyUI 中调整连接。

旧版宽高占位符仍可使用：在 API 工作流的对应输入中写字符串
`"width": "PH_W"`、`"height": "PH_H"`，
并在配置页填写 `PH_W` 和 `PH_H`。选择分辨率预设后，它们会被替换成数字。

### 多个 LoRA

把模型放进 ComfyUI 可识别的 LoRA 目录，通常是 `models/loras`，
再刷新或重启 ComfyUI。在「工作流尺寸与 LoRA」中：

- 自动读取 ComfyUI 提供的 LoRA 文件名，也可以手动填写准确的名称。
- 修改已有 `LoraLoader` / `LoraLoaderModelOnly` 节点的文件名和权重。
- 没有 LoRA 节点时，点「添加 LoRA」，可添加多条，按顺序串联。
- 标准 LoRA 可分别调整模型权重和文本／CLIP 权重；「仅模型」只调整模型权重。
- 新增 LoRA 需要选择接入的采样器；没有可识别的共用 CLIP 支路时可尝试「仅模型」。

未接入实际出图支路的已有 LoRA 不会应用修改。
模型不存在或 ComfyUI 缺少对应节点时，出图会报错。

### 二次采样

展开「二次采样专区」，选择：

| 方式 | 行为 |
| --- | --- |
| 保持工作流原设置 | 保留已有流程，不额外加入二采 |
| 调整已有二采 | 调整识别到的第二轮及后续采样的步数、CFG、降噪等参数，以及支持的放大节点 |
| 新增二采 | 在支持的单轮工作流中加入 latent 放大和第二个 `KSampler` |

自动新增要求单轮 `KSampler` 直接连接 `VAEDecode` / `VAEDecodeTiled`。
新增二采继承初采的模型、LoRA、提示词及种子，
默认放大 `1.5` 倍、`20` 步、降噪 `0.35`。
已有二采或无法安全识别连接时，请调整已有节点或先在 ComfyUI 中连接。

已有 `KSamplerAdvanced` 会显示开始／结束步数等相应选项；
由其他节点计算的参数保持连接。
采样器和调度器需填写 ComfyUI 支持的名称，
提高放大倍数会增加显存占用和耗时，降噪越高通常变化越大。

## 角色库

角色库是可选功能，数据库不随源码提供。
默认位置是 `server/character_lookup/characters.db`。

- **已有数据库：**把 `characters.db` 放到上述目录。
- **已有 CSV：**把 `danbooru_character.csv` 放到同一目录，在项目根目录运行：

  ```bash
  python server/character_lookup/build_db.py --skip-download
  ```

- **没有数据文件：**运行下面的命令，下载数据并建库；也支持 `--proxy` 参数：

  ```bash
  python server/character_lookup/build_db.py
  ```

配置页会显示角色库是否就绪，也提供测试查询。
需要使用其他数据库位置时，可在启动前将环境变量 `CHARACTER_DB` 设为其绝对路径。

多角色描述尽量写清名字和作品，例如「白子（蔚蓝档案）和初音未来合影」。
系统一次最多匹配四位角色；遇到多个候选时提示选择，未匹配的部分仍按原描述生成。

继续写同一角色时，在同一个会话保持「角色搜索」和「上下文」开启。
上一轮有多位角色时，用「她们／他们」可沿用全部；
只修改其中一位，请写明角色名。角色特征能帮助提示词生成，
实际还原效果仍取决于模型、LoRA 和工作流。

## 参考图识别

在「配置 → VLM 图片识别」填写支持视觉输入的 OpenAI 兼容 API 地址、
API Key 和模型名称，保存后可上传一张或多张参考图。

参考图先由视觉模型转换成文字，再参与 LLM 提示词生成；
当前流程不会自动把上传图片接入 ComfyUI 的图生图、ControlNet 或其他图像节点。
不上传参考图时，无需配置 VLM；上传后识别失败会中止本轮生成。

## 插件

把可信插件的文件夹复制到 `server/data/plugins/`。
在网页「插件」页点击「重新扫描并载入代码」，启用插件并保存设置。
插件默认关闭，可配置执行顺序和 JSON 参数，部分插件也提供网页面板。

插件可以接入四个阶段：
`before_prompt`、`after_prompt`、`before_workflow`、`after_generate`，
并提供自己的 API 和前端面板。
再次生成跳过前两个提示词阶段，仍执行工作流和结果处理阶段。

- **试用示例：**复制 [`examples/plugins/prompt_suffix/`](examples/plugins/prompt_suffix/) 到插件目录。
- **自己制作：**阅读 [插件制作教程](docs/plugins.md)，包含完整示例、配置、接口、调试和发布步骤。
- **更新或卸载：**先在网页停用并保存，再替换或删除文件，最后重新扫描。

插件是在网站进程内执行的 Python 代码，没有沙盒；
只安装可信插件。网页不提供在线市场、ZIP 上传或自动安装第三方依赖。

## MCP 连接

HTTP 直连可提交工作流、等待结果和取图。
需要 MCP 时，再安装并启用：

```bash
python -m pip install "comfy-mcp" "comfy-cli>=1.14.0" -i https://pypi.tuna.tsinghua.edu.cn/simple
```

这两个包不在网站的基础依赖中，启动脚本不会自动安装它们。
在「配置 → ComfyUI 与 MCP」填写：

| 字段 | 说明 |
| --- | --- |
| comfy-mcp 命令 | 可用命令名；独立环境中可填 `C:/你的环境/Scripts/comfy-mcp.exe` |
| ComfyUI 工作区目录 | 启用 MCP 时填写实际的 ComfyUI 根目录；便携版也要指向内层 `ComfyUI` 文件夹 |
| comfy 命令路径 | 若子进程找不到 `comfy`，填 `C:/你的环境/Scripts/comfy.exe` |

勾选「启用 MCP」，保存后点「重启引擎」。
MCP 路径会尝试工作流校验，并通过工具提交任务和取图；
相关调用失败时会尝试 HTTP 回退。两种连接方式使用相同的工作流，
图片效果主要由工作流和模型决定。

右上角状态表示：

- **MCP 引擎：**MCP 进程和 ComfyUI HTTP 检测都在线。
- **HTTP 直连：**ComfyUI HTTP 检测在线，MCP 未连接或已关闭。
- **离线：**当前 ComfyUI HTTP 检测未连通，先检查服务和地址。

状态徽标表示连接状态，不保证具体工作流及其模型、节点都可用。

## 手机与局域网访问

网站默认监听 `0.0.0.0:5000`，本机用 <http://127.0.0.1:5000> 访问。
手机和平板连到同一局域网后，使用电脑的局域网 IP，
例如 `http://192.168.1.10:5000`。

1. 在 Windows 防火墙允许网站所用 Python 的专用网络访问，或放行网站端口。
2. 在「配置 → 访问保护」设置访问口令并保存。
3. 在手机浏览器输入口令后使用。

手机访问的是喵梓网站，ComfyUI 和本地模型的请求仍由运行网站的电脑发出。
它们与网站在同一台电脑时，可继续监听 `127.0.0.1`，
不需要仅为了手机访问而开放 ComfyUI 或 LLM 端口。
服务在其他电脑上时，填写那台电脑实际可达的地址。

`0.0.0.0` 用于服务监听；浏览器和 API 配置中使用 `127.0.0.1` 或实际 IP。
需要修改网站监听地址或端口时，可在启动前设置 `HOST`、`PORT` 环境变量。

### 按 IP 分开创作

不需要注册或登录账户。页面上的「IP 创作空间」显示当前访问 IP：

- 不同 IP 的会话、消息、历史上下文、生成图片、NSFW 和保存的工作流参数分别保存。
- 同一个 IP 的设备或浏览器共享同一份数据；IP 变化时会进入另一个空间，原数据仍保留。
- 本机的 `127.0.0.1`、`::1` 统一归为本机空间。
  升级前的会话和图片也保留在该空间，首次访问时不会被其他设备领取。
- ComfyUI、LLM、工作流文件、常驻正向内容、角色库及插件配置仍为所有访问者共用。
  旧版保存的工作流参数继续作为默认值，各 IP 自己保存的参数优先。
- 系统按实际连接地址识别访问者，不采用 `X-Forwarded-For` 等请求头。
  通过反向代理访问时，通常会共用代理的 IP 空间；同一个公网出口的访问者也可能共用空间。

IP 划分用于区分创作数据，不是账户权限系统；访问口令仍是全局共用的口令。
生成任务使用同一台 ComfyUI，仍按原有队列逐个执行。

## 更新与备份

### Windows 更新

1. 先关闭运行网站的窗口。
2. 双击项目根目录的 [`update.bat`](update.bat)。
3. 脚本直接更新，不再询问代理地址；未配置代理时直连。
4. 更新完成后重新运行 `start.bat`，缺少的 Python 依赖默认通过清华源安装。

需要代理时，可在项目根目录手动指定 HTTP(S) 地址，不支持 SOCKS：

```bash
python update.py --proxy http://127.0.0.1:7890
```

代理只用于这次源码更新，不修改系统或 Git 的全局配置。
Python 依赖通过[清华 PyPI 镜像](https://mirrors.tuna.tsinghua.edu.cn/help/pypi/)安装，
源码更新仍从 GitHub 获取。

- **Git 安装：**要求当前在 `main` 分支，且没有修改已跟踪的项目文件；
  然后快进更新 `origin/main`。
- **ZIP 安装：**替换有变化的同名项目文件，不删除额外文件；
  被替换的旧文件备份在 `.miaozi-update-backups/`。
- **保留的数据：**配置、会话、图片、角色数据库和 CSV、已安装插件及其配置；
  额外工作流文件也会保留。修改过的项目自带文件可能被 ZIP 更新替换，可从备份恢复。

不要把个人配置、密钥、数据库或生成图片提交到公开仓库。

## 常见问题

| 问题 | 先检查什么 |
| --- | --- |
| 双击启动后提示找不到 Python | 安装 Python，并确认终端能运行 `python --version` |
| LLM 连接失败 | 检查基础 API 地址、模型名称和 Key；地址不要重复包含 `/chat/completions` |
| 提示词一直等待，最后 180 秒超时 | 对比关闭上下文后的耗时，检查模型速度和思考输出；当前请求没有关闭思考或限制输出 token 的参数 |
| ComfyUI 显示离线 | 确认 ComfyUI 已启动，保存正确地址后再测试；地址要带 `http://` 或 `https://` |
| 找不到 `comfy-mcp` | 只用 HTTP 可关闭 MCP；要用 MCP，检查安装环境、命令路径和工作区是否存在，再重启引擎 |
| MCP 找不到模型或节点 | 确认工作区指向实际 ComfyUI 目录，`comfy` 命令可用 |
| 有图但网站拿不到输出 | 检查工作流是否包含图片保存节点，保存节点 ID 是否正确，并查看服务日志 |
| 提示工作流是画布格式 | 在 ComfyUI 中重新导出 API 格式 |
| 角色搜索没有结果 | 检查数据库是否建立、两个角色检索开关是否开启；同名角色尽量加作品名 |
| 上传参考图失败 | 检查 VLM 地址和视觉模型是否支持图片输入；只做文字生图可移除参考图 |
| LoRA 或二采设置不生效 | 确认节点在出图支路上、参数没有由其他节点计算，且工作流满足对应接入条件 |
| 图片混入上一轮内容 | 关闭「上下文」，或降低历史轮数，再发起新创作 |
| 下载 ZIP 后启动脚本弹 SmartScreen | 确认来源可信后，可在下载 ZIP 的属性中解除锁定，再重新解压 |
| 更新脚本提示有本地改动 | 保存或提交改动后再更新；不要直接覆盖自己修改的文件 |
